# ROAM 与 CSAE 团标的边界

> 用途：明确界定 ROAM 开源项目与 CSAE 团标《智能网联汽车 高度自动驾驶车辆运营管理异常事件处置规范》的关系、范围划分与协作机制
> 受众：CSAE 团标起草组成员、ROAM 项目协作者、行业专家
> 状态：v0.1，2026-05-14

---

## 一、为什么需要这份边界说明

随着 CSAE 团标预研启动通知发出，越来越多的行业专家、车企、运营商、检测机构表达了参与意愿。在起草组扩展、协作启动之前，有必要明确以下三个问题：

1. ROAM 开源项目和 CSAE 团标，到底是什么关系？
2. ROAM 框架中的哪些内容会进入团标，哪些不会？
3. ROAM 框架中的具体设计（如 10 种运营模式、三层决策架构、KPI 阈值等），是否就是团标的最终定稿？

本文档对这三个问题给出明确回答，作为起草组协作的共同基础。

---

## 二、ROAM 与 CSAE 团标的关系

### ROAM 是 superset，CSAE 团标是 subset

ROAM（Remote Operations & Anomaly Management）是一个开源研究框架，自 2026 年 1 月起在 GitHub 持续维护，定位是国际化、研究导向、持续演化。

CSAE 团标《智能网联汽车 高度自动驾驶车辆运营管理异常事件处置规范》是中国本土化的、由起草组共识决定的标准化产出，从 ROAM 框架中选择适合标准化的部分，结合中国国情、商业模式与监管实际制定。

两者关系的核心是：

```
┌─────────────────────────────────────────────────┐
│ ROAM 开源项目 (superset)                          │
│ 国际研究框架 · 持续演化 · 不约束行业自由实现        │
│                                                  │
│  ┌────────────────────────────────────────────┐ │
│  │ CSAE 团标 (subset)                          │ │
│  │ 中国本土 · 起草组共识 · 标准化条款           │ │
│  └────────────────────────────────────────────┘ │
│                                                  │
│ ROAM 包含但不限于团标范围：                        │
│ • Incident Database（国际化事件库）               │
│ • 学术论文（TR-A / SAE / ISO 工作文档）           │
│ • 关键技术研究                                     │
│ • 商业模式探索（含 L4 数据驱动保险新模式）         │
│ • 跨域案例（无人机远程运营等）                    │
└─────────────────────────────────────────────────┘
```

ROAM 范围必然大于 CSAE 团标。原因有三：

第一，ROAM 包含开源代码、模型、数据集等技术性产出，这些不属于标准化范畴，开源给行业自由实现。

第二，ROAM 包含商业模式探索（如 L4 数据驱动保险新模式），属于市场化产出，不进入强制性或推荐性标准。

第三，ROAM 包含国际标准对比、跨域案例等研究内容，这些是立项背景与方法论参考，不直接转化为标准条款。

### CSAE 团标必然小于 ROAM。原因有三：

第一，团标必须聚焦于"可标准化"的内容。ROAM 中的某些设计（如 10 种运营模式分类）可能在标准化层面过于复杂，需要起草组按"可标准化、对中国市场有意义"原则裁剪。

第二，团标必须结合中国国情。ROAM 中的国际对标内容（加州 DMV Article 3.7、Markey 报告、德国 StVFernLV 等）作为立项背景参考，但中国版本的具体条款需要本土化重写。

第三，团标必须由起草组共识决定。ROAM 是单一项目方维护的研究框架，团标是多方共建的标准化产出，必然存在差异。

### 团标的对外边界：企业内部运营治理，不是道路通行管理

除了"ROAM 与团标"这一内部边界，团标还有一条同样重要的对外边界。

团标管的是「企业内部运营治理」——运营企业的远程运营中心（ROC）在异常事件发生后如何分级决策、责任如何划分、用什么 KPI 评价。团标不管「道路通行管理」——车辆在道路上的具体通行行为（速度、距离、信号装置使用、让行等），以及交警如何管理道路交通。

后者属于公安部交管体系与全国道路交通管理标准化技术委员会（SAC/TC 576）的范畴，已有 GA/T 2388-2026《智能网联汽车 道路测试与示范应用安全通行规范》等标准覆盖。团标在起草过程中应严守这一边界：凡涉及车端在道路上的通行行为，一律引用 GA/T 2388-2026，不重复规定。

同理，团标也不规定车辆型式认证（由 GB/T 44721 等单车标准覆盖），不规定测试阶段的主体要求（由 GB/T 43766-2024 覆盖），不规定车端到国家平台的数据上报通道（由 GB/T 国标在研覆盖）。

团标与上述标准的完整定位关系，详见 [`02-positioning-vs-gb-draft.md`](02-positioning-vs-gb-draft.md) 第五部分的标准坐标系。

## 三、范围划分清单

下面把 ROAM 框架中的内容按"是否进入团标"分为三类。

### A. 拟进入团标（结构性章节，共识基础较好）

这些是任何团标都必须有的结构性章节，争议较小，可以由起草组在 ROAM 现有内容基础上整理形成：

- 术语和定义
- 缩略语
- 范围与适用对象
- 总体框架
- KPI 评价体系框架（条目分类，不含具体阈值）
- FRIP 模板章节结构（应包含哪些必填项）
- 试验方法骨架（验证手段类型）

### B. 待起草组共识决定（核心内容，由专家共建）

这些是 ROAM 框架中具体设计的部分，需要由起草组成员单位用真实运营数据、实操经验、监管反馈共同校准。当前 ROAM 中的设计仅为备选方案，最终是否进入团标、以何种形式进入，由起草组共识决定：

#### B1. L4 运营模式分类

当前 ROAM 列出 10 种运营模式作为备选清单（M1 Robotaxi 到 M10 专用环境）。

具体数量、分类边界、是否全部纳入团标，由起草组按"可标准化、对中国市场有意义"原则共识决定。已有专家反馈：模式数量过多，标准化难度较大，后续可能进行调整与删减。

#### B2. 决策架构层级

当前 ROAM 提出三层 Layer 1/2/3 决策架构与 70/25/5 的占比估值。

具体层级数量、定义、各层占比、甚至是否采用分层架构作为核心方法论，均待起草组共识与中国实操数据校准。70/25/5 的占比是基于公开资料的初步估值，没有真实运营数据支撑，必须以中国市场的实际数据替换。

#### B3. 异常事件场景分类

当前 ROAM 提出 6 大类 29 子场景的分类体系。

具体分类粒度（大类是否合并、子场景是否细化或合并）由起草组细化。

#### B4. 责任划分维度

当前 ROAM 提出执行 / 决策 / 技术 / 法律 / Override / Avoidance / 监管反馈 七个维度。

具体维度数量、维度定义、各维度的责任分配规则，由起草组共识决定。

#### B5. KPI 具体阈值

当前 ROAM 提出 16 项 KPI，部分参考加州 DMV Article 3.7（如 30 秒紧急响应、2 分钟紧急地理围栏退出等阈值）。

中国版本的 KPI 阈值必须以中国运营数据校准，不能直接采用加州数值。

#### B6. 责任矩阵法律维度

当前 ROAM 中的法律维度部分，缺乏中国判例支撑，需要公安部道路交通安全研究中心主导重写。

#### B7. FRIP 模板本土化

当前 ROAM 的 FRIP 模板参考加州 DMV § 227.42(i)，本土化部分需要公安部道路交通安全研究中心主导。

#### B8. 试验方法细则

当前 ROAM 第 12 章的试验方法仅有骨架，需要中汽中心等检测机构主导细化。

### C. 不进入团标（保留在 ROAM 开源层面）

这些内容属于 ROAM 项目的自有范畴，不进入团标：

- 异常事件库的国际化部分（持续国际化收集，作为研究素材）
- 国际标准对比（仅作为团标立项背景参考，不作为团标条款）
- 关键技术细节（开源给行业自由实现，不写入标准）
- 商业模式探索（如 L4 数据驱动保险新模式，市场化产出）
- 学术论文（独立产出，TR-A、SAE、ISO 工作文档等）
- 跨域案例（无人机远程运营等方法论借鉴）

## 四、材料状态披露

ROAM 框架 v1.2 是借助 AI 工具进行结构化整理的初步研究框架，基于公开的国内外标准、法规、行业报告以及作者团队的实践经验。

ROAM 与 CSAE 团标的关系：

- ROAM 是开源研究框架（superset），持续国际化演化
- CSAE 团标《智能网联汽车 高度自动驾驶车辆运营管理异常事件处置规范》是其中可以标准化的子集（subset）
- 团标的具体内容（包括运营模式分类、决策架构层级、KPI 阈值、责任矩阵维度、FRIP 本土化、试验方法等），需要起草组成员用真实运营数据和实操经验校准
- 团标内容必须结合中国国情、商业模式和监管实际，由起草组成员单位共识决定，不等同于 ROAM 框架本身
- ROAM 中的运营模式数量、决策架构层级与占比等具体设计，均为当前阶段的备选方案，后续可能进行调整、删减或重新定义

本框架不替代以下专业判断：

- 真实运营数据的实证校准
- 中国法律责任划分的判例支撑
- 跨企业协作中的真实摩擦点识别
- 监管侧的政治可行性评估

在 CSAE 团标起草过程中，所有条款的最终采纳由起草组专家审议确定。本项目持续欢迎行业专家的反馈、修订与共建。

## 五、起草组协作机制

为确保 ROAM 与 CSAE 团标的边界清晰、协作顺畅，建议起草组采取以下机制。

### 5.1 双轨并行

ROAM 开源项目继续在 GitHub 维护，作为研究框架持续演化；CSAE 团标走 CSAE 标准化流程，由起草组共建。

两者互相滋养但定位独立：ROAM 为团标提供初稿素材与方法论参考，团标的共识结论也可以反馈到 ROAM 框架的迭代中。

### 5.2 章节认领制

起草组下设三个 SubGroup（SG-1 术语与架构 / SG-2 责任与法律 / SG-3 KPI 与场景），由不同牵头单位主导。每章节明确主笔与审议专家，团标发布时在前言中署名。

### 5.3 ROAM 内容的引用规则

起草组成员可以参考 ROAM 中的现有内容，但不应假设 ROAM 中的具体设计就是团标的最终条款。所有 ROAM 内容在团标语境下都是"备选方案"，最终采纳由起草组共识决定。

### 5.4 商业秘密保护

各起草组成员单位贡献的真实运营数据、案例与经验，在团标中以脱敏、聚合、去标识化的方式呈现，不涉及单一企业的商业秘密。

### 5.5 异议处理

对 ROAM 现有内容有异议的起草组成员，可以通过 GitHub Issue 或起草组会议直接提出。重大架构性争议（如运营模式数量、决策架构层级、责任维度等）通过起草组共识机制解决。

## 六、对潜在参与者的说明

如果您正在考虑加入起草组，请理解以下几点：

第一，ROAM 不等于 CSAE 团标。加入起草组意味着参与团标的共建，而不是接受 ROAM 现有内容作为既定方案。

第二，您的实操经验、运营数据、行业洞察是团标质量的核心保障。ROAM 提供的是初步的结构化框架，真正让团标有价值的，是起草组成员带来的真实世界的判断与校准。

第三，ROAM 持续欢迎反馈与修订。即使您不加入 CSAE 团标起草组，也欢迎在 GitHub 通过 Issue 或 PR 贡献意见。
